```bash
python -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/python -m pytest -q          # тести (34)

python task1.py <source> [dest]        # завдання 1, dest за замовчуванням: dist

python task3.py                        # завдання 3, бенчмарк (~25 с)
```

## Завдання 1 - копіювання й сортування файлів за розширенням

`copy_files(src, dest)` рекурсивно обходить `src`: для директорії викликає саму себе, файл копіює в `dest/<розширення>/` (файли без розширення йдуть у `no_extension/`). Помилки доступу (`OSError`/`PermissionError`) перехоплюються для кожного елемента окремо, тож обробка решти файлів продовжується. Файли з однаковими назвами не перезаписуються (`a.txt`, `a_1.txt`, …). Якщо `dest` лежить усередині `src`, вона пропускається.

## Завдання 2 - сніжинка Коха

`koch_points(level, size)` рекурсивно будує вершини фракталу (3·4ⁿ відрізків), `draw()` малює їх через `turtle`. Рівень рекурсії задається аргументом командного рядка або вводиться з клавіатури.

## Завдання 3 - порівняння сортувань

Час виміряно за допомогою `timeit` на чотирьох типах даних (random, sorted, reversed, nearly_sorted) розміром від 100 до 10 000 елементів. Timsort - це вбудована `sorted()`. Точні значення залежать від машини та запуску, тому висновки нижче сформульовано через тенденції, а не через конкретні числа. Щоб отримати таблицю замірів на своїй машині, запустіть `python task3.py`.

### Перевірка теоретичних оцінок

| Алгоритм | Найкращий | Середній / найгірший | Що показали заміри при збільшенні N у 10 разів |
|---|---|---|---|
| Вставками | O(n) | O(n²) | на random / reversed час зростає приблизно у 100 разів (квадратично); на sorted - приблизно у 10 разів (лінійно) |
| Злиттям | O(n log n) | O(n log n) | час зростає трохи більше ніж у 10 разів незалежно від типу даних |
| Timsort | O(n) | O(n log n) | на sorted - лінійне зростання, на random - як O(n log n) |

- **Сортування вставками** квадратичне на випадкових і обернених даних і вже на кількох тисячах елементів стає найповільнішим на порядки. Проте на відсортованих і майже відсортованих даних воно лінійне й обганяє сортування злиттям.
- **Сортування злиттям** стабільно працює за O(n log n) і майже не залежить від порядку вхідних даних, але не використовує наявну впорядкованість.
- **Timsort** поєднує переваги обох: знаходить у даних уже впорядковані послідовності (runs), короткі з них доповнює сортуванням вставками (де воно найшвидше), а потім зливає їх, як сортування злиттям. Тому на відсортованих даних він лінійний, а в загальному випадку працює за O(n log n).

### Висновки

1. Timsort на всіх наборах даних найшвидший: на порядок-два швидший за сортування злиттям і на кілька порядків швидший за сортування вставками на великих невпорядкованих масивах.
2. Найбільший відрив Timsort має на відсортованих і майже відсортованих даних. Це наслідок алгоритму (адаптивність до впорядкованих послідовностей і вставки на малих фрагментах), а не лише швидкої реалізації на C усередині CPython.
3. Сортування вставками доцільне лише для дуже малих або майже відсортованих масивів. Саме так його й використовує Timsort.
4. Для практичних задач слід використовувати вбудовані `sorted()` / `list.sort()`: вони швидші, стабільні й добре протестовані. Власні реалізації мають сенс лише для навчання або для специфічних вимог.
